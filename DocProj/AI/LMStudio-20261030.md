## LLM recommendations

### Targets

#### Size

| Model size | Recommendation                                     |
|------------|----------------------------------------------------|
| 3B–4B      | Very fast, but potentially less capable            |
| 7B–8B      | Sweet spot — Excellent balance                     |
| 12B–14B    | Recommended — More capable, somewhat slower        |
| 20B–32B    | Possible with CPU/RAM offloading, but not ideal    |
| 70B+       | Not practical on this machine                      |

#### Quantization

| Quantization | Recommendation                           |
|--------------|------------------------------------------|
| Q4_K_M       | Best starting point                      |
| Q5_K_M       | Better quality, somewhat more memory     |
| Q6_K         | Higher quality, more memory              |
| Q8_0         | Usually unnecessary for your GPU         |
| Q2 / Q3      | Avoid unless memory is extremely limited |

* Favor Q4_K_M and Q5_K_M.

#### Context length

Don't underestimate context length.

For software development, context length is particularly important. You might eventually want to give an LLM several C# classes, interfaces, configuration files, and documentation simultaneously.

Start at 8K or 16K. Increase it when you have sufficient memory.

### Models

#### 1- Qwen3-8B — Best everyday model

* General reasoning · Programming · Documentation
* Recommended quantization: Q4_K_M
* For coding tasks, you can lower temperature to approximately 0.2–0.3 for more consistent output.
* For complex architectural problems, enable thinking mode.

Qwen3 is a strong general-purpose model with good coding and reasoning capabilities. It supports both thinking and non-thinking modes, which is useful because you can choose between faster answers and more deliberate reasoning.

Use it for:

- Designing classes and interfaces.
- Reviewing code.
- Explaining unfamiliar code.

## LM Studio  configuration

Regardless of which model you're using, I'd configure LM Studio with the following general settings.

| Setting               | Recommendation                   |
|-----------------------|----------------------------------|
| Inference backend     | CUDA                             |
| GPU offload           | As many layers as fit            |
| Flash Attention       | On                               |
| KV cache quantization | Q8_0                             |
| Context length        | 8K–16K depending on model        |
| Evaluation batch size | 512 initially                    |
| CPU threads           | 6–8                              |
| Keep model in memory  | Enabled when regularly using it  |

### Other settings

I'd use different settings depending on the task.

| Setting        | General chat   | IDE coding  | Agent tasks    |
|----------------|----------------|-------------|----------------|
| Temperature    | 0.6            | 0.2         | 0.2            |
| Top P          | 0.95           | 0.9         | 0.9            |
| Context        | 16K            | 16K         | 16K            |
| Repeat penalty | 1.05           | 1.05        | 1.05           |
| Thinking mode  | On when useful | Usually off | On when useful |

* For IDE use, prioritize responsiveness.
* For agent use, prioritize reliable instruction following and tool calling.

### Additional

* **GPU offloading**  
This is particularly important. You want as much of the model as possible running on your RTX 4070 rather than your CPU.

* **Flash Attention**  
Enable it. It can improve attention performance and reduce memory consumption.

* **KV cache quantization**  
Q8_0 can reduce the memory required for longer conversations while maintaining good quality.

* **Context length**  
Don't automatically set every model to its maximum context length. Larger context windows consume additional memory, even when you aren't using all of that context.

* **Batch size**  
512 is a reasonable starting point. If you encounter memory problems, try 256.
